# アプリケーション仕様書

## 1. 概要

### 1.1. アプリケーション名
割り勘計算機 (立替計算アプリ)

### 1.2. 目的
複数人での共同購入や立替が発生するイベントにおいて、複雑な費用精算を自動化し、簡略化することを目的とする。

### 1.3. 対象ユーザー
友人同士やグループなど、複数人でイベントに参加し、費用を共同で管理する必要がある人々。

## 2. 機能仕様

### 2.1. 画面構成
単一のページで構成され、主に以下のセクションから成る。

- **チケット料金セクション**: 各種チケットの単価を入力する。
- **費用項目セクション**:
    - チケット (固定)
    - ビアサーバー (固定)
    - 食材 (固定)
    - 動的に追加された項目
- **動的項目追加ボタン**: 新しい費用項目を追加する。
- **総合収支セクション**: 全ての項目を集計し、各参加者の最終的な精算額を表示する。

### 2.2. 機能一覧

#### 2.2.1. 料金設定
- 「チケット料金」セクションで、「通し券」「テント券」「駐車券」の単価をそれぞれ設定できる。
- 設定した単価は、チケット費用の計算に自動的に使用される。

#### 2.2.2. 項目別精算
- 「チケット」「ビアサーバー」「食材」および動的に追加された各費用項目に対して、以下の操作が可能。
    - **参加者選択**: チェックボックス形式で、その項目に参加するメンバーを選択できる。
    - **支払額入力**: 各参加者がその項目で立て替えた金額（または購入したチケットの数量）を入力できる。
- 入力された情報に基づき、項目ごとの合計金額と一人当たりの負担額が自動で計算・表示される。

#### 2.2.3. 動的項目追加・削除
- 「新しいテーブルを追加」ボタンを押すことで、「ガソリン代」「宿泊費」など、任意の名前を持つ新しい費用項目を自由に追加できる。
- 追加された項目は、他の項目と同様に精算処理が可能。
- 各動的項目のテーブルには削除ボタンがあり、不要になった項目を削除できる。

#### 2.2.4. 総合収支計算
- 全ての費用項目を集計し、最終的な総合収支をテーブル形式で表示する。
- テーブルには、各参加者が「最終的にいくら支払うか（マイナス表示）」「いくら受け取るか（プラス表示）」が明確に示される。
- さらに、総合収支の内訳として、各費用項目（チケット、ビアサーバー等）での個別の収支も表示される。
- 「折り返し表示に切り替え」ボタンにより、スマートフォンの画面でも見やすいように、テーブルの表示スタイル（横スクロール/折り返し）を切り替えることができる。

#### 2.2.5. データ永続化
- 入力されたすべての情報（料金設定、参加者選択、支払額など）は、自動的にブラウザの`localStorage`に保存される。
- これにより、ユーザーがページを再読み込みしたり、一度ブラウザを閉じたりしても、入力したデータが失われることはない。

#### 2.2.6. UI/UX
- **レスポンシブデザイン**: スマートフォンでの表示と操作に最適化されている。
- **入力欄の自動幅調整**: 金額入力欄は、入力された数値の桁数に応じて幅が自動で調整される。
- **デフォルト値**: 空の入力欄には `0` が表示され、未入力を防ぐ。
- **エラー表示**: 不適切な操作やデータの不整合があった場合、画面上部にエラーメッセージが表示される。

## 3. アーキテクチャ

### 3.1. 設計思想
本アプリケーションは、Vanilla JavaScriptで構築されており、状態管理にReduxライクな単一方向データフローを採用している。これにより、データの流れを予測可能にし、メンテナンス性と拡張性を高めている。

### 3.2. データフロー
アプリケーションのデータフローは以下の通り。

1.  **ユーザー操作**: ユーザーがチェックボックスを切り替えたり、金額を入力したりする。
2.  **Action Dispatch**: UI層のイベントリスナーがユーザー操作を検知し、`dispatch(action)`を呼び出す。`action`は `{ type: 'ACTION_TYPE', payload: { ... } }` という形式のオブジェクト。
3.  **状態変更**: `state.js`内の`reducer`関数が`action`を受け取り、`type`に応じて状態（State）を更新する。
4.  **永続化**: 状態が変更されると、計算結果を除く新しい状態が自動的に`localStorage`に保存される。
5.  **UI更新**: 状態変更が完了すると、`subscribe`（購読）されていた`renderApp`関数が呼び出される。
6.  **再描画**: `renderApp`は、新しい状態オブジェクトを元に、画面の各コンポーネント（テーブル、参加者リストなど）を再描画する。
7.  **計算実行**: UIの再描画後、`calculateAndDispatch`関数が呼び出され、現在の状態を元に全ての費用の再計算が行われる。
8.  **計算結果の保存**: 計算結果は `UPDATE_CALCULATION_RESULTS` アクションとして再度`dispatch`され、状態の一部として保存される。これにより、計算結果がUIに反映される。

### 3.3. モジュール構成
`app/js/` ディレクトリ配下に、責務ごとに分割されたモジュールが配置されている。

- **`main.js`**: アプリケーションのエントリーポイント。イベントリスナーの設定や初期化処理を行う。
- **`state.js`**: アプリケーション全体の唯一の状態ストア。状態の保持、更新、購読、永続化の責務を負う。
- **`calculation.js`**: すべての割り勘計算ロジックを集約。状態から計算に必要な情報を取得し、精算結果を返す。
- **`ui.js`**: 全体のレンダリングを統括。状態変更に応じて各UIコンポーネントの描画関数を呼び出す。
- **`components/*.js`**: UIの各部品（テーブル、参加者リスト、動的セクション）を生成・更新する責務を持つモジュール群。
- **`config.js`**: 参加者リストなど、アプリケーションの基本的な設定情報。
- **`constants.js`**: 文字列キーやIDなど、アプリケーション全体で利用される定数。

### 3.4. 計算ロジック
計算は `calculation.js` の `performCalculations` 関数で行われる。

- **項目別計算**:
    1. 各項目（チケット、ビアサーバー等）ごとに、参加しているメンバーのリストを取得する。
    2. 参加メンバーが支払った金額の合計を算出する（`項目別合計費用`）。
    3. `項目別合計費用` を参加人数で割り、`一人当たり費用` を算出する。
- **個人別収支計算**:
    1. 各参加者について、すべての項目を横断して収支を計算する。
    2. ある項目における個人の収支は `(その項目で個人が支払った額) - (その項目の一人当たり費用)` で求められる。
    3. 全ての項目における個人の収支を合計したものが、その参加者の `総合収支` となる。
    - プラスの場合：他の人からお金を受け取る
    - マイナスの場合：他の人にお金を支払う

## 4. データ構造

### 4.1. 状態 (State)
アプリケーションは、`state.js`内で単一のオブジェクトとして状態を管理する。

```javascript
{
  // 各参加者の入力値や選択状態を保持
  participantInputValues: {
    '参加者A': {
      'テント券': 1, // チケット枚数
      '駐車券': 0,
      '手数料': 330,
      'ビアサーバー': 5000,
      '食材': 2000,
      'main_checked': true, // チケット項目への参加/非参加
      'beer_checked': true, // ビアサーバー項目への参加/非参加
      // ...動的項目のキーがここに追加される...
    },
    // ...他の参加者のデータ...
  },

  // チケット単価
  ticketPrices: {
    '通し券': 15000,
    'テント券': 4000,
    '駐車券': 3000
  },

  // 動的に追加されたセクションの情報
  dynamicSections: [
    { id: 'dynamic-section-166...', name: 'ガソリン代' },
    { id: 'dynamic-section-167...', name: '宿泊費' }
  ],

  // 計算結果 (localStorageには保存されない)
  calculationResults: {
    '参加者A': {
      totalPayment: 4330, // チケット関連の支払い合計
      beerServerPayment: 5000,
      foodPayment: 2000,
      balance: -1000, // チケット関連の収支
      beerBalance: 1500,  // ビアサーバーの収支
      // ...各項目の収支...
      totalBalance: 500 // 全項目を合計した最終収支
    },
    // ...他の参加者の計算結果...
  }
}
```

### 4.2. localStorage
以下のキーでデータがブラウザに保存される。

- **`participantInputValues`**: 上記 `participantInputValues` オブジェクトのJSON文字列。
- **`ticketPrices`**: 上記 `ticketPrices` オブジェクトのJSON文字列。
- **`dynamicSections`**: 上記 `dynamicSections` 配列のJSON文字列。
