# 開発ガイドライン

このドキュメントは、立替計算アプリの開発に参加する新しい開発者向けに、プロジェクトのコーディング規約、コミットメッセージのルール、プルリクエストのプロセスなどをまとめたものです。

## 1. コーディング規約

- **JavaScript**: ESLintとPrettierを使用しています。コードをコミットする前に、`npm run lint:fix`を実行して自動修正し、`npm run format`を実行してフォーマットを適用してください。
- **JSDoc**: すべての関数、クラス、エクスポートされた変数にはJSDocコメントを記述してください。これにより、コードの可読性と保守性が向上します。
- **命名規則**: 変数名、関数名、クラス名にはキャメルケース（camelCase）を使用してください。定数にはすべて大文字とアンダースコア（SNAKE_CASE）を使用してください。
- **マジックナンバー**: コード内のマジックナンバーは、`src/js/constants.js`に定義された定数を使用してください。

## 2. コミットメッセージのルール

[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)の仕様に従ってください。これにより、コミット履歴が読みやすくなり、自動化ツールとの連携が容易になります。

**フォーマットの例:**

```
<type>(<scope>): <subject>

[optional body]

[optional footer(s)]
```

**主な`type`:**

- `feat`: 新機能の追加
- `fix`: バグ修正
- `docs`: ドキュメントの変更
- `style`: コードのスタイル変更（フォーマット、セミコロンなど、ロジックに影響しない変更）
- `refactor`: リファクタリング（バグ修正や機能追加ではないコード構造の変更）
- `test`: テストの追加や修正
- `chore`: ビルドプロセスや補助ツールの変更、ライブラリの依存関係の更新など

**`scope`の例:**

- `ui`: UI関連の変更
- `calculation`: 計算ロジック関連の変更
- `state`: 状態管理関連の変更
- `deps`: 依存関係の更新

**例:**

```
feat(ui): Add dynamic section creation

This commit introduces the ability to add new dynamic sections to the application.
Users can now create custom tables for various expenses.
```

## 3. プルリクエストのプロセス

1. **ブランチの作成**: 作業を開始する前に、`main`ブランチから新しいフィーチャーブランチを作成してください。ブランチ名は`<type>/<short-description>`の形式にすることをお勧めします（例: `feat/add-dynamic-sections`）。
2. **開発**: 変更を加え、テストを記述し、ローカルでリンティングとテストを実行して、すべてがパスすることを確認してください。
3. **コミット**: 上記のコミットメッセージのルールに従って、意味のあるコミットを頻繁に行ってください。
4. **プッシュ**: 作業ブランチをリモートリポジトリにプッシュしてください。
5. **プルリクエストの作成**: GitHub上でプルリクエストを作成し、変更内容、目的、関連するIssueなどを明確に記述してください。
6. **レビュー**: チームメンバーにコードレビューを依頼してください。レビューコメントに対応し、必要に応じて変更を加えてください。
7. **マージ**: レビューが承認されたら、`main`ブランチにマージしてください。

## 4. テストの実行

- ユニットテストを実行する: `npm test`
- リンティングを実行する: `npm run lint`
- リンティングを自動修正する: `npm run lint:fix`
- コードをフォーマットする: `npm run format`

## 5. アプリケーションの確認方法

このプロジェクトには、ローカル開発サーバーはセットアップされていません。アプリケーションの動作を確認するには、プロジェクトのルートにある`app/index.html`ファイルを直接ブラウザで開いてください。
