# 立替計算アプリ

複数人での共同購入や立替が発生するイベントでの費用精算を簡単にするためのWebアプリケーションです。

## 主な機能

- **レスポンシブデザイン**: スマートフォンでの表示と操作に最適化されています。
- **項目別の精算**: 「チケット代」「ビアサーバー代」「食材代」など、費用項目ごとに参加者を選択して、割り勘計算ができます。
- **動的な項目追加**: 事前に定義された項目以外にも、「ガソリン代」や「宿泊費」など、新しい費用項目を自由に追加・削除できます。
- **総合収支の詳細表示**: 全ての項目を集計し、各参加者が最終的に「いくら支払うか」「いくら受け取るか」を自動で計算します。さらに、チケット、ビアサーバー、追加項目など、どの項目でいくらの収支があったのか、その内訳も一覧で確認できます。
- **データ自動保存**: 入力した内容は自動的にブラウザに保存されるため、ページを再読み込みしてもデータが消えることはありません。
- **直感的なUI**:
  - 参加者のチェックリストは、タップしやすいようにデザインされています。
  - 金額入力欄は、入力された数字の長さに応じて幅が自動で調整され、数字が隠れることなく表示されます。
  - 空の入力欄は、分かりやすいように「0」がデフォルトで表示されます。
  - 新規テーブルの参加者リストは、チェックを入れた順番に関わらず、常にメインの参加者リストと同じ順番で表示され、一貫性のあるビューを提供します。
  - **表示切替可能な総合収支**: 総合収支テーブルは、スマートフォンの縦画面でも見やすいように、横スクロール表示と、テキストを折り返して全体を一度に確認できる表示をボタン一つで切り替えられます。

## 使い方

1. **チケット料金の入力**:
   - 「チケット料金」セクションで、通し券やテント券などの単価を入力します。

2. **各項目への参加者の選択**:
   - 「チケット」「ビアサーバー」「食材」などの各セクションで、その費用項目に参加するメンバーのチェックボックスをオンにします。

3. **新しい項目の追加（任意）**:
   - 「新しいテーブルを追加」ボタンをタップし、「タープ代」など新しい費用項目を追加します。

4. **支払金額の入力**:
   - 各テーブルで、メンバーが立て替えた金額（購入したチケットの枚数や、支払った費用）を入力します。

5. **総合収支の確認**:
   - ページ下部の「総合収支」テーブルで、各メンバーの最終的な精算額（支払う/貰う）と、その詳細な内訳を確認します。

## ファイル構成 (app/jsディレクトリ)

アプリケーションのソースコードは`app/js`ディレクトリに格納されています。

```
app/js/
├── components/         # UIコンポーネントのモジュール
│   ├── dynamicSection.js # 動的セクション（追加テーブル）のレンダリングとイベント
│   ├── participant.js  # 参加者リストのレンダリング
│   └── table.js        # 各種テーブルの生成と更新
├── utils/              # 汎用的なユーティリティ関数
│   └── format.js       # 数値フォーマットなど
├── __tests__/          # Jestによるテストコード
│   ├── calculation.test.js
│   └── state.test.js
├── calculation.js      # 計算ロジックを担当
├── config.js           # 参加者リストなどの設定情報
├── constants.js        # アプリケーション全体で使用される定数
├── main.js             # アプリケーション全体を初期化するエントリーポイント
├── state.js            # Reduxライクな中央集権的な状態管理ストア
└── ui.js               # 全体のレンダリングの統括とUIイベントリスナーの設定
```

## 開発者向け情報

- **状態管理と単一方向データフロー**: アプリケーションの状態は`state.js`に集約され、Reduxに似た単一方向のデータフローを採用しています。
  1. UIイベントが発生すると、`dispatch(action)`が呼び出される。
  2. `state.js`内の`reducer`が`action`に応じて状態を変更する。
  3. 状態が変更されると、`subscribe`されたコールバック（`renderApp`）が実行される。
  4. `renderApp`は新しい状態を元にUI全体を再描画する。
  このアーキテクチャにより、データの流れが予測可能になり、デバッグとメンテナンスが容易になっています。
- **コンポーネントベースのUI**: UIの各部分は`components`ディレクトリ内で機能ごとにモジュール化されており（`table.js`, `participant.js`など）、それぞれが状態を受け取ってUIをレンダリングする責務を負っています。
- **BEM (Block, Element, Modifier)**: CSSのクラス名はBEMの考え方に基づいて命名されており、スタイルがどの要素に対応するかが分かりやすくなっています。
- **CSSカスタムプロパティ**: 色やフォントサイズなどの共通の値はCSS変数として定義されており、デザインの変更が容易です。
- **`<template>`タグ**: JavaScript内でのHTML文字列の組み立てを避け、`index.html`内の`<template>`タグにHTMLの断片を定義しています。これにより、HTML構造の変更が容易になっています。
- **イベント委譲**: 動的に生成される要素のイベントは、親要素でイベントを捉えるイベント委譲パターンで処理しており、安定性とパフォーマンスを向上させています。
- **テスト**: `Jest`と`JSDOM`を使用したユニットテストが`app/js/__tests__`に配置されています。ビジネスロジック（状態管理、計算）を中心にテストを記述しています。
- **入力バリデーションとエラーハンドリング**: ユーザー入力のバリデーションや、localStorageからのデータ読み込み、計算処理など、各所でエラーハンドリングが行われています。開発者向けの重要なエラーや警告は、ブラウザのコンソールに出力されます。

### Ver. 4 (状態管理ベースアーキテクチャへの刷新)

- **UIモジュールの分割**: 巨大な`ui.js`を、責務に基づいて`components`ディレクトリ以下の小さなモジュール（`table.js`, `participant.js`, `dynamicSection.js`）に分割。
- **状態管理の導入**: Reduxライクな中央集権的ストア（`state.js`）を導入。`dispatch`と`subscribe`を用いた単一方向データフローを確立し、アプリケーション全体の状態変更を予測可能にした。
- **計算ロジックの分離**: 計算ロジックを状態の更新から完全に分離。UIのレンダリング後に計算がトリガーされ、その結果が再び状態としてストアに送られるデータフローを構築。
- **テストの拡充**: `Jest`を導入し、リファクタリングされた状態管理（`state.js`）と計算ロジック（`calculation.js`）に対するユニットテストを大幅に拡充。
- **不要なコードの削除**: 古い`eventBus`やテストファイルを削除し、コードベースをクリーンアップ。
